# GreenRetail build fix — 2026-09-21

## Problem fixed
The domain entities had already been converted to integer Kobo storage:
- `Sale.*Kobo`
- `SaleItem.*Kobo`
- `Payment.AmountKobo`
- `CartLine.UnitPrice` as `Money`

Several older use cases and view models still referenced the previous decimal properties (`Sale.Total`, `Payment.Amount`, `SaleItem.UnitPrice`, etc.). That produced the 27 compiler errors reported by `dotnet build`.

## Changes
- Updated `CompleteSaleUseCase` to persist/read `Sale`, `SaleItem`, and `Payment` using Kobo fields.
- Updated `RegisterViewModel` to pass `Money.Kobo` directly instead of treating `Money` as `decimal`.
- Updated `SecurityOps` receipt verification and recent-sales query to use `TotalKobo`.
- Updated the daily report query to aggregate sales/payments in Kobo and convert to `Money` only at the presentation boundary.

## Important
This environment does not contain the .NET SDK, so a local `dotnet build` could not be executed here. The fix was checked against the reported compiler errors and by static reference inspection.

Run on Windows in the project folder:

```powershell
dotnet build -f net10.0-windows10.0.19041.0
```

## Next engineering item
The current EF Core migration/snapshot still describes the older decimal `Sales`, `SaleItems`, and some related columns while the C# entities use Kobo fields. That schema-model drift should be resolved with a deliberate migration before relying on upgrades of an existing database. Do not delete or recreate a production database merely to hide this mismatch.
